# Day 1 Trainer Evaluation Checklist

## Purpose
Use this checklist to evaluate participant performance during Day 1 labs and final challenge.

## Evaluation Criteria

### Prompt Quality
- Context provided clearly
- Constraints included explicitly
- Expected output format defined

### Engineering Discipline
- Analysis performed before coding
- Requirements validated before implementation
- Ambiguities captured and discussed

### Context Management
- Repository scope reduced to relevant files
- Unrelated components avoided

### Validation
- Build and test executed after changes
- AI outputs were verified, not accepted blindly

### Testing Strategy
- Test matrix created before test generation
- Boundary and negative scenarios included
- Regression tests written for defects

### Debugging Quality
- Root cause identified with evidence
- Minimal fix applied without unrelated refactor

### Architecture Quality
- Separation of concerns maintained
- External dependencies abstracted properly
- Dependency injection respected

### Security and Safety
- Credentials managed securely
- Tool actions assessed by risk level
- Destructive operations guarded

### AI Judgment
- Participants challenged weak AI suggestions
- Assumptions were identified and validated

## End-of-Day Deliverables Checklist
- Working ASP.NET Core solution
- Domain model
- Order service
- Inventory abstraction
- Inventory integration
- Unit tests
- Regression test
- Claude-enabled code-review endpoint
- Tool-use demonstration
- Agentic workflow demonstration
- Updated documentation
- PR summary

## Overall Learning Outcome
Effective AI-assisted development is disciplined engineering amplified by AI, not AI replacing engineering judgment.
